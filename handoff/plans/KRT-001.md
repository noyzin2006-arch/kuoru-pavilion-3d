# KRT-001｜颐和园廓如亭实时三维数字复原——唯一轮次执行规划

**版本**：2026-10-25。**指令对象**：本机执行 Agent。以下新文件路径均为本方案指定新建的文件，非既有文件。本轮仅阅读 brief、plan-spec、design-quality-bar 三份许可文件，禁止读取其他项目文件或借用现成3D模型。资料结论分为 H（简报交叉核实）、I（本计划推算）、S（场景示意），不允许把 I/S 说成测绘实况。

## 1. 需求、范围、非目标与验收

**用户原话**：“启动sflipmloop，做个极度精致、还原、逼真的颐和园廓如亭模型。用网页展示。从头做，不许查看已有文件。”

**明确产出**：从零程序化建造、实时WebGL可探索的亭阁文博展示静态网站；能一眼辨别八角双檐，近看柱网斗栱彩画，拆开看构造并分清史实与推断。

**范围内**：①八方月台、虎皮石台基与垂带踏跺、宇墙木门；②八角三圈40柱/柱础、枋梁、六檩、斗栱、雀替笼花板、重檐八脊攒尖屋顶/吻兽/圆宝顶、藻井、八匾、坐凳金砖和彩画；③昆明湖水面、东堤、十七孔桥、南湖岛、万寿山佛香阁**仅示意性**远景；④程序化PBR贴图、程序化大气与PMREM、时刻/季节联动；⑤轨道缩放平移、六镜头、八热点、逐层分解、平面剖切、1.70m比例人、首次引导；⑥桌面移动界面、所有状态、无障碍、纯函数测试、浏览器测试、截图、公开静态部署。

**范围外**：VR/AR、后端/账号、云端API、付费资源/素材、下载第三方几何文件、角色骨骼、实测地理测绘、全园区孪生、宣传为毫米级真实扫描；不复制其他项目任何文件。

**可判定验收编号**：
- AC01 `npm run build`与`npm test`退出0；测试数量取命令实际统计。
- AC02 开发/构建服务上用Playwright在375×812和1440×900实测浏览器 console error 0、pageerror 0、跨源请求0；画布至少完成两次真实绘制。

## 4. 体验设计

**信息架构**：一级“廓如亭展厅”；其下二级四面板“构件详情、场景控制、复原依据、帮助”，层级≤2；切换不生成额外网页。位置标识永远显示“廓如亭 · 结构复原 / 非激光扫描”。

**核心旅程**：进入→显示真实阶段0/4（环境）1/4（柱网）2/4（檐顶）3/4（光照）4/4（就绪）的渐进文案→直接看见亭主角（禁止强制片头）→用左键拖、滚轮缩放、右键平移→点击“斗栱”空间标注→镜头聚焦并展开说明H/I等级→拉“分解”滑杆观察分层→点击“恢复全景”回到原状。**次旅程**：选“黄昏/秋季”→光色、水色、树色同步变→选“藻井仰视”→点击剖切看柱网→开启身高1.70m灰色人参照→切“依据”查看推定参数→恢复默认春季正午。

**首屏布局**：默认相机eye(28,16,29)，target(0,5,0)，FOV35°；主亭应占可用画布高度60–76%，宝顶留顶空≥8%；右侧320px控制区域不可覆盖宝顶。≥1280左信息区240px、右操作区320px、中央画布；1024–1279左160右280；768–1023左信息折叠右280；480–767画布60dvh，controls移到下方、详情变sheet；≤479时顶栏56px、12px边距、控制选项每组2×2、按钮44px、允许纵向滚动但禁止横向文档滚动。375px首屏须看见画布与“构件/分解”两枚主要按钮。200%放大允许折行，不能定高裁掉文案。

**6镜头（世界米）**：总览 eye(28,16,29)→target(0,5,0)；正南(0,9,32)→(0,5.2,0)；正东(32,9,0)→(0,5.2,0)；梁架(12,7.7,10)→(1.5,5.6,1)；藻井(0,3.4,1.4)→(0,7.8,0)；台阶(19,3.3,12)→(4,1,0)。普通模式distance [8,85]、polar[.15,1.48]、target XZ ±18和Y[1,10.5]；藻井模式distance[1.5,12]、允许仰视、禁用破坏视角的pan，退出时恢复普通限制。镜头动画800ms `cubic-bezier(.2,.8,.2,1)`，用户拖动立即取消预设过渡，不得二次跳跃。平移`OrbitControls`方向以官方文档与实测为准，手写镜头移动后必须调用controls.update()。

**四态具体全局文案**：空“还没有选中的构件，从画面标记或目录开始”；加载“正在建立瓦面与彩画（第2/4步）…”（步骤必须来自实际阶段）；错误“你的浏览器没有成功启动实时三维，请刷新或阅读文字结构说明”；成功“廓如亭模型就绪，拖动旋转、滚轮缩放”。轻量模式提示“已降低远景密度，建筑尺寸不变”。切换时刻成功toast“已切换至秋季·黄昏”；无内部堆栈。

**几何代码细节**：
- `makeOctagon` 顶点绕正八边形，八角面积恒等式用于单测。平面只用一套模型配置`PAVILION_CONFIG`定义，函数接收配置不可读取DOM。
- 上下檐以每个八角扇区的径向分段带生成`BufferGeometry`；法线按顶点三角形顺序统一，外表方向朝上；双面材质仅用于藻井可见背面，不拿DoubleSide掩盖法线错误。自檐口至尖顶分16径向圈、每八边12角向细分（上檐）；曲线 `height(r)=lerp(eaveY,ridgeY,pow(clamp(1-r/rmax),1.15)) -0.16*(r/rmax)^8 +0.08*exp(-((r-0.8*rmax)/(0.11*rmax))²)`；上下檐各用自己的rmax、eaveY、ridgeY。檐口高由curve公式结果与标称差需在构建时统一归一到指定值。
- 24柱外圈在八条边逐条按t={0,1/3,2/3}取点（下一边t=0给共享角，避免t=1重复），中内各8点按同样角序。柱座和木柱分离ID，拆解时不得改变实体尺寸。
- 屋顶瓦不以大平面单贴图冒充：沿每面内的径向瓦陇用`InstancedMesh`布置半圆筒样瓦件；每陇沿径向0.28m节距，参考半径0.095m、瓦搭接0.045m；横向自适应保持可见连续；屋脊以几何扫掠管条，端部收口；高LOD目标≤18,000瓦片实例（两个檐合计），低LOD降低4倍并用法线纹理。禁止纹理图案随视角滑动。
- 八角檐口边缘、飞檐、椽头均要能在“梁架”镜头分辨；室内藻井必须实际有深度，不能仅用一张画贴在平板。
- 彩画基于程序化CanvasTexture：1024×256，以纹饰回旋、对称旋子、24条金线为参数绘制在额枋UV，金线宽取画面像素3（纹饰总高256px，约1.17%），主色木朱#6E2422/石绿#28695B/群青#284B78/赭黄#B89147/金#BE9B55（全置scene材质表），采用分区线框+重复旋子花，不仿造无法确认的真迹图案；匾额中文若字体字形/资料未确认，只绘制外侧“廓如亭”和内侧“匾额题辞待核”小标，不能虚构乾隆诗或《文心雕龙》正文；网页详情标明文本未核。
- 彩画结构先做到跨梁对齐，再添加纹饰；极细金线在低LOD压成单色视觉带，避免移动摩尔纹。

### 5.5 可靠性、状态机和边界
- `reducer` 对分解和剖切夹在[0,100]；未识别热点ID必须回到无选择且给说明；不把unknown字段写入state；镜头输入NaN重置总览。
- 两种模式**组合规则**：分解与剖切可同时启用，但先在原始局部坐标执行剖切shader/discard，再对组做分解平移；热点锚点跟随实例组matrixWorld更新，避免光标漂浮；人物不参与剖切、除非用户关闭比例尺。
- 逐层分解定义：台基/柱网不动；坐凳+0.15m·t；下檐与枋梁+1.4m·t；上檐+3.0m·t；宝顶+3.8m·t，其中t=expl ode/100（实际变量名`explode`，无空格）；热点可见时跟随对应组件。
- 剖切：固定法向(+1,0,0)的垂直平面，X由-15m平移到+15m（对应0–100）；仅在sectionEnabled时应用 `THREE.Plane` + renderer.localClippingEnabled、材质`clippingPlanes`，文案说明“展示内部结构，非测绘剖面”；关闭立刻移除裁剪以避免材质共享污染；正反向测试。
- 页面不可滚动事件与轨道冲突：三维canvas `touch-action:none`，其他页面仍可正常纵向滚动；仅对画布阻止默认手势；window.blur与visibilitychange取消拖拽和镜头动画，返回时不能跳动。
- Context lost 监听`webglcontextlost`调用preventDefault，暂停RAF/显示“图形环境中断，正在恢复”；`webglcontextrestored`重新创建材质环境/资源、重播当前状态；连续2次恢复失败切换文本版而非死循环。
- ResizeObserver遇0宽高不重设aspect；节流到RAF、重算camera.aspect与projectionMatrix；旋转手机同理。
- 资源生命周期：每一组geometry/material/texture统一登记`ResourceRegistry`，renderer.destroy销毁RAF、controls、监听器、target和WebGLRenderer；换时刻只dispose旧PMREM target，绝不销毁共享材质。
- 数据体量：8热点/6镜头，无列表分页；若未来热点>200才引分页，本轮不实现虚拟列表。长汉字段落换行，标签限2行`line-clamp:2`加title/aria-label全文；禁直接`innerHTML`插入资料。
- 关闭网络：构建输出的JS/CSS/纹理本地化；不使用`fetch`外部链接、外部图片、Google Fonts、telemetry、远程错误上报、ServiceWorker；“来源”链接在明确用户点击时允许跳转离开网站，但页面自身不得预取。
- 性能预算：默认构件几何≤350k三角形（高画质≤650k）、draw calls<450（low<220）、静态dist未压缩JS≤1.5MiB（无大依赖）、生成纹理≤100MiB显存、首屏可交互≤2.5秒本机冷启动；如超标先实例化瓦和植被，再缩远景，再降DPR，不能先砍关键柱数/屋形。

**实际操作流程**（不是只截图）：预览启动→首次引导→键盘跳过→轨道一整圈→放大/缩小/右键平移→切四时刻×四季→8热点打开详情→六镜头中藻井仰视和台阶低视角→分解0/50/100→剖切0/50/100→开启1.70m人物→重置；每步观测Canvas确实更新且focus和toast对应。至少按“春午正南、秋夕总览、冬夜、藻井内部、分解100%、剖切50%”截6张桌面图，375px下至少2张（默认+详情）。另保留loading、空、强制WebGL失败三种UI截图。

**E2E具体断言**：
- page.goto("/")后`waitForFunction(()=>window.__exhibit?.phase==='ready')`（执行时`src/main.js`仅在`import.meta.env.DEV`或`E2E_TEST`条件暴露有限只读测试探针，不暴露写状态后门到生产）；`page.on('console')`记录error，`page.on('pageerror')`记录异常，`page.on('request')`只接受origin相同或data/blob；禁止以 `page.route('**/*', abort)` 人为屏蔽外联来骗测试。
- 实测 canvas boundingClientRect>0、读取renderer.info.render.calls>0（仅测试探针）、真实拖拽后camera matrix变化；按5种视口验证文档不横溢；对比度单测直接用§3所定义的色值及实际组件CSS背景；通过键盘切换季节并断言scene当前季节同步。

- PMREM切换连续100次在同质量档下`renderer.info.memory.textures`相对初始基线浮动≤3、`geometries`浮动≤3（允许缓存但不准线性上涨）；关闭视图后RAF=0。
- 通过Playwright在page.addInitScript模拟contextUnavailable/用户减少动效/Storage写入异常，确认可读fallback或不阻断渲染。禁止改生产功能只为测试通过。

**实测性能方法**：分别在1440×900 DPR1与375×812 DPR1使用Chrome Performance + Navigation Timing，服务本地dist，无冷缓存的首次加载（新context），从navigationStart到用户能操作3D且UI ready为交互时间；每档跑5次取中位数、记录最大值；首屏≤2.5s要求中位数与最大值均满足才标PASS。稳定30s记录FPS中位值，high目标≥50fps桌面、low≥30fps，任何持续10s FPS<25触发low并告知。CLS用PerformanceObserver收集`layout-shift`排除hadRecentInput，求和≤.1。交互反馈用performance.mark从click到下一paint，最多100ms；轻量操作完成≤300ms（材质环境重建这类明确异步任务允许>300ms但必须100ms内先反馈）。
